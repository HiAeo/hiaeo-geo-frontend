### 4.3 容器化部署

```yaml
# docker-compose.yml 示例
version: '3.8'

services:
  api:
    build: ./api
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DB_HOST=mysql
      - REDIS_HOST=redis
    depends_on:
      - mysql
      - redis
    deploy:
      replicas: 3
      resources:
        limits:
          cpus: '1'
          memory: 2G

  worker:
    build: ./worker
    environment:
      - NODE_ENV=production
      - REDIS_HOST=redis
    depends_on:
      - redis
    deploy:
      replicas: 2
      resources:
        limits:
          cpus: '2'
          memory: 4G

  mysql:
    image: mysql:8.0
    volumes:
      - mysql_data:/var/lib/mysql
    environment:
      - MYSQL_ROOT_PASSWORD=${DB_PASSWORD}
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 4G

  redis:
    image: redis:7-alpine
    volumes:
      - redis_data:/data
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 1G

volumes:
  mysql_data:
  redis_data:
```

## 5. 安全架构

### 5.1 认证授权

```
┌─────────────────────────────────────────────────────────────────┐
│                         认证流程                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  用户 ──► 登录 ──► 验证凭证 ──► 生成JWT ──► 返回Token          │
│                                                                 │
│  请求 ──► API ──► 验证Token ──► 解析Claims ──► 权限校验        │
│                            │                                    │
│                     Token过期? ──► 是 ──► 返回401               │
│                            │                                    │
│                            │ 否                                 │
│                            ▼                                    │
│                       权限通过 ──► 业务处理                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

| 安全措施 | 实现方式 |
|----------|----------|
| 认证 | JWT + Refresh Token |
| 授权 | RBAC 角色权限模型 |
| 加密 | AES-256 + HTTPS |
| 防护 | WAF + DDoS防护 |
| 审计 | 操作日志全量记录 |

### 5.2 数据安全

| 数据类型 | 存储方式 | 加密 |
|----------|----------|------|
| 用户密码 | MySQL | bcrypt哈希 |
| Token | Redis | 内存存储 |
| 敏感信息 | MySQL | AES-256加密字段 |
| 文件 | COS | 云端加密 |
| 日志 | MongoDB | 脱敏存储 |

## 7. 技术选型理由

### 7.1 为什么选择 NestJS？

- ✅ TypeScript原生支持，类型安全
- ✅ 模块化架构，易于微服务拆分
- ✅ 装饰器语法，代码简洁
- ✅ 生态丰富，文档完善
- ✅ 支持 GraphQL + REST 双协议

### 7.2 为什么选择 MySQL？

- ✅ 事务支持，数据一致性有保障
- ✅ 生态成熟，运维成本低
- ✅ 主从复制，读写分离成熟方案
- ✅ JSON字段支持，灵活扩展

### 7.3 为什么选择 Redis？

- ✅ 高性能缓存，降低数据库压力
- ✅ Session存储，分布式会话共享
- ✅ 消息队列，异步任务解耦
- ✅ 限流计数器，防止接口滥用
