## ADR-001: 产品架构从"独立模块"转向"闭环流水线"

**日期：** 2026-05-11
**状态：** 已采纳
**决策者：** 产品团队 + 开发团队

### 背景

原架构中，智库、诊断、策略、执行、监控各模块独立工作，数据不流通。用户需要手动在各模块间跳转，信息重复填写，效率低下。

### 决策

采用"用户输入网址，AI 接管闭环优化"的架构设计：

1. **状态机联动**：各模块通过 workflow_state 状态机联动
2. **Agent 大脑**：统一调度所有模块，串联数据流
3. **自动循环**：定时诊断 → 策略生成 → 执行 → 监控

### 后果

**正面：**
- 用户操作从 10+ 步减少到 3 步
- 数据自动流转，减少重复工作
- 可追溯、可干预、可信任的闭环

**负面：**
- 系统复杂度增加
- 需要更多测试覆盖
- 错误传播风险增加

## ADR-002: 工作流状态存储在 Brand 实体

**日期：** 2026-05-11
**状态：** 已采纳

### 背景

需要一个统一的机制来跟踪品牌在 GEO 全流程中的位置。

### 决策

在 Brand 实体中增加 `workflow_state` JSON 字段：

```typescript
interface BrandWorkflowState {
  knowledge: ModuleState;
  diagnosis: ModuleState;
  strategy: ModuleState;
  execution: ModuleState;
  monitor: ModuleState;
  lastDiagnosisId?: string;
  lastStrategyTaskId?: string;
  lastExecutionId?: string;
  updatedAt?: string;
}
```

### 替代方案

| 方案 | 优点 | 缺点 |
|-----|------|-----|
| Brand 实体 JSON 字段 | 简单，与品牌绑定 | JSON 查询性能差 |
| 独立表 workflow_state | 查询灵活 | 增加关联复杂度 |
| Redis 缓存 | 高性能 | 持久化问题 |

### 选择理由

MVP 阶段优先简单性，JSON 字段足够满足需求。后续如需复杂查询，可迁移到独立表。

## ADR-003: URL 抓取使用 cheerio 而非 Puppeteer

**日期：** 2026-05-11
**状态：** 已采纳

### 背景

需要从用户提供的官网 URL 自动抓取内容，填充到品牌智库。

### 决策

使用 `axios + cheerio` 进行轻量级网页抓取：

- **axios**：HTTP 请求
- **cheerio**：HTML 解析

### 替代方案

| 方案 | 优点 | 缺点 |
|-----|------|-----|
| cheerio | 轻量、快速 | 无法处理 JS 渲染 |
| Puppeteer | 完整浏览器渲染 | 资源消耗大，Vercel 不支持 |
| Playwright | 功能强大 | 同上 |

### 选择理由

大多数企业官网是静态页面，cheerio 足够。Puppeteer/Playwright 需要完整浏览器环境，在 Vercel Serverless 无法运行。

## ADR-004: 后端部署从 Vercel 迁移到 Railway

**日期：** 2026-05-11
**状态：** 计划中（未执行）

### 背景

当前后端部署在 Vercel Serverless，存在以下限制：
- 不支持原生 Node.js 模块（better-sqlite3、bcrypt）
- 不支持定时任务
- 不支持 WebSocket 长连接
- 超时限制严格

### 决策

迁移后端到 Railway：

**Railway 优势：**
- 原生 Node.js 支持
- 定时任务内置
- PostgreSQL + Redis 一键部署
- WebSocket 支持
- 按使用量计费（有免费层）

### 迁移步骤

1. 在 Railway 创建项目，连接 GitHub repo
2. 添加 PostgreSQL 和 Redis 插件
3. 配置环境变量
4. 推送代码触发部署
5. 验证 API 可用
6. 更新前端环境变量

## ADR-005: 向量数据库选择 Pinecone

**日期：** 2026-05-11
**状态：** 计划中（未执行）

### 背景

品牌智库需要向量检索能力，支持语义搜索和内容推荐。

### 决策

选择 Pinecone Starter（免费层）：

- 3 个索引
- 10万向量免费
- 无需运维
- SDK 支持完善

### 替代方案

| 方案 | 成本 | 难度 | 备注 |
|-----|------|-----|-----|
| Pinecone | 免费层足够 | ⭐ | 推荐起步 |
| Qdrant (自托管) | 免费 | ⭐⭐ | 长期成本控制 |
| Supabase pgvector | 基于现有 | ⭐ | 如已用 Supabase |
| Milvus | 需运维 | ⭐⭐⭐ | 大规模部署 |

### 选择理由

MVP 阶段优先快速启动，Pinecone 免费层足够使用。

## ADR-008: AI 引擎多提供商架构

**日期：** 2026-04
**状态：** 已采纳

### 背景

需要支持多个 AI 引擎，以便：
- 成本优化（不同引擎价格不同）
- 容错（单一引擎不可用时切换）
- 功能差异（不同引擎擅长不同任务）

### 决策

建立 AI 引擎适配层（AI Module），统一接口：

```typescript
interface AIProvider {
  chat(messages: Message[]): Promise<string>;
  embed(text: string): Promise<number[]>;
}
```

支持提供商：
- OpenAI (GPT-4, GPT-3.5)
- Claude (Claude 3)
- DeepSeek
- 百度文心（待集成）

### 成本考虑

| 引擎 | 输入价格 | 输出价格 | 适用场景 |
|-----|---------|---------|---------|
| GPT-4 | $0.03/1K | $0.06/1K | 高质量生成 |
| GPT-3.5 | $0.0015/1K | $0.002/1K | 日常任务 |
| Claude 3 | $0.015/1K | $0.075/1K | 长文本 |
| DeepSeek | ¥0.001/1K | ¥0.002/1K | 中文优先 |
