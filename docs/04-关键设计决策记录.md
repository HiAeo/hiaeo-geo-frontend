## ADR-001: 前端技术选型 - Vue 3 + Vite

**状态:** 已接受
**日期:** 2026-05-08

### 背景

需要为魔鲸 Geo 选择前端框架，平衡开发效率、性能和团队熟悉度。

### 决策

选择 **Vue 3 + Vite** 作为前端技术栈。

### 因素

| 技术 | 优势 | 劣势 |
|------|------|------|
| Vue 3 |  Composition API、响应式、性能优秀 | 团队需要熟悉新语法 |
| Vite | 极速 HMR、现代化构建 | 生态相对 React 较小 |
| React | 生态丰富、社区大 | 学习曲线、配置复杂 |
| Next.js | SSR/SSG 支持、SEO 友好 | 更适合内容型网站 |

### 结论

Vue 3 + Vite 组合提供了最佳的开发体验和性能平衡，同时团队对 Vue 较为熟悉。

## ADR-002: 后端技术选型 - NestJS

**状态:** 已接受
**日期:** 2026-05-08

### 背景

需要选择后端框架，支持模块化架构、类型安全和团队协作。

### 决策

选择 **NestJS** 作为后端框架。

### 因素

| 技术 | 优势 | 劣势 |
|------|------|------|
| NestJS | 模块化、装饰器、TypeScript 原生支持 | 学习曲线 |
| Express | 轻量、灵活 | 缺乏结构化 |
| Fastify | 性能极高 | 生态较小 |
| Django/Flask | Python 生态 | 需跨语言 |

### 结论

NestJS 提供了：
- 模块化的代码组织
- 原生 TypeScript 支持
- 丰富的生态系统（TypeORM、Passport 等）
- 良好的可测试性

## ADR-003: 部署策略 - Vercel

**状态:** 已接受（有已知问题）
**日期:** 2026-05-08

### 背景

需要为前后端选择托管平台，平衡成本、便利性和功能。

### 决策

前后端都部署在 **Vercel** 平台。

### 因素

| 平台 | 优势 | 劣势 |
|------|------|------|
| Vercel | 前端优化、SSR 支持、CI/CD、内网访问 | Serverless 不支持原生模块 |
| Netlify | 静态站点优化 | Serverless Functions 功能较弱 |
| AWS | 功能强大 | 配置复杂、成本高 |
| 独立服务器 | 完全控制 | 运维成本高 |

### 结论

Vercel 的以下特性使其成为最佳选择：
- 免费额度充足
- 自动 CI/CD
- 内网穿透
- 前端优化
- Serverless Functions

### ⚠️ 已知限制

Vercel Serverless **不支持**以下原生 Node.js 模块：
- `better-sqlite3`
- `sqlite3`
- `sharp`
- 其他原生绑定模块

### 解决方案

**临时方案：**
- 创建轻量级 `api/index.js` 作为 Vercel API Handler
- 使用 JavaScript 实现替代 NestJS 编译版本

**长期方案：**
- 迁移到支持原生模块的平台（Railway/Render）
- 或使用纯云服务（MySQL、Redis、向量数据库）

## ADR-004: AI 引擎架构 - 适配器模式

**状态:** 已接受
**日期:** 2026-05-08

### 背景

需要支持多个 AI 引擎（OpenAI、Claude、Gemini、DeepSeek），同时保持代码整洁和可扩展。

### 决策

采用 **适配器模式（Adapter Pattern）** 设计 AI 引擎层。

### 架构

```
┌─────────────────────────────────────┐
│          AI Module (调用方)          │
└─────────────────┬───────────────────┘
                  │
                  ▼
┌─────────────────────────────────────┐
│        AI Adapter Interface          │
│         (统一接口定义)               │
└─────────────────┬───────────────────┘
                  │
    ┌─────────────┼─────────────┐
    ▼             ▼             ▼
┌───────┐    ┌───────┐    ┌───────┐
│OpenAI │    │Claude │    │Gemini │
│Adapter│    │Adapter│    │Adapter│
└───────┘    └───────┘    └───────┘
```

### 实现

每个 AI 引擎实现统一的 `AIAbstractAdapter` 接口：

```typescript
interface AIAbstractAdapter {
  name: string
  chat(messages: Message[]): Promise<AIResponse>
  generateEmbedding(text: string): Promise<number[]>
}
```

### 优势

1. **解耦** - 业务逻辑与具体 AI 实现分离
2. **可替换** - 可以轻松切换 AI 引擎
3. **可测试** - 可以使用 Mock Adapter 进行测试
4. **可扩展** - 添加新引擎只需实现接口

## ADR-005: 数据持久化策略

**状态:** 待确定
**日期:** 2026-05-08

### 背景

当前系统使用内存存储，数据在服务重启后会丢失。需要设计持久化方案。

### 候选方案

| 方案 | 数据库 | 缓存 | 向量存储 | 状态 |
|------|--------|------|---------|------|
| 方案 A | MySQL | Redis | Milvus | 推荐 |
| 方案 B | PostgreSQL | Redis | Pinecone | 备选 |
| 方案 C | MySQL | - | Pinecone | 简化 |

### 决策

**暂未最终确定**，但倾向方案 A：

- **MySQL** - 关系型数据存储
- **Redis** - 缓存、会话、实时数据
- **Milvus** - 向量数据存储（知识库语义搜索）

### 待解决问题

1. 云服务成本评估
2. Vercel 部署兼容性
3. 数据迁移策略

## ADR-006: 前端状态管理

**状态:** 已接受
**日期:** 2026-05-08

### 背景

需要选择状态管理方案，处理用户认证、品牌数据、诊断结果等全局状态。

### 决策

使用 **Vue 3 Composition API + localStorage** 组合，暂不引入 Vuex/Pinia。

### 因素

| 方案 | 优势 | 劣势 |
|------|------|------|
| Composition API | 原生、轻量、组合式 | 需自行实现共享 |
| Pinia | 官方推荐、DevTools 支持 | 增加依赖 |
| Vuex | 成熟、DevTools 支持 | 4.x 才支持 Vue 3 |
| localStorage | 简单、无依赖 | 仅持久化 |

### 结论

当前阶段使用 Composition API + localStorage：
- **localStorage** - 持久化用户信息、Token
- **Composition API** - 组件内状态和逻辑复用
- **API 层** - 通过 API 封装处理全局数据

### 未来考虑

如项目复杂度增加，可引入 Pinia：
```bash
npm install pinia
```

## ADR-007: 认证授权设计

**状态:** 已接受
**日期:** 2026-05-08

### 背景

需要实现安全的用户认证和授权机制。

### 决策

采用 **JWT Token** 认证方案：

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│    登录      │      │   生成 Token │      │   返回给前端  │
│  用户名/密码 │ ──── │  JWT Access  │ ──── │  存储 local  │
│              │      │  Refresh Token│     │  Storage     │
└──────────────┘      └──────────────┘      └──────────────┘
       │
       │                    ┌──────────────┐
       │                    │   后续请求   │
       └─────────────────── │  Header:    │
                            │  Authorization:│
                            │  Bearer <token>│
                            └──────────────┘
```

### Token 设计

| Token 类型 | 有效期 | 用途 |
|-----------|--------|------|
| Access Token | 15 分钟 | API 访问 |
| Refresh Token | 7 天 | 刷新 Access Token |

### 角色设计

| 角色 | 前缀 | 权限 |
|------|------|------|
| brand | `/app/*` | 品牌用户工作台 |
| admin | `/manage/*` | 管理员后台 |

## ADR-008: 知识库向量存储

**状态:** 已接受
**日期:** 2026-05-10

### 背景

需要实现品牌知识库的语义搜索功能，支持 AI 驱动的智能建议和内容生成。

### 决策

采用 **向量数据库** 存储知识库内容，支持语义相似度搜索。

### 架构

```
用户查询
    │
    ▼
┌─────────────────────────────────────┐
│       文本向量化 (Embedding)         │
│   使用 AI 引擎生成 1536 维向量       │
└─────────────────┬───────────────────┘
                  │
                  ▼
┌─────────────────────────────────────┐
│          向量数据库检索               │
│     相似度搜索 (Cosine Similarity)  │
└─────────────────┬───────────────────┘
                  │
                  ▼
┌─────────────────────────────────────┐
│           返回相关知识条目            │
│     结合原始文本进行 AI 生成         │
└─────────────────────────────────────┘
```

### 候选方案

| 向量数据库 | 优势 | 劣势 |
|-----------|------|------|
| Milvus | 功能强大、开源、可自部署 | 配置复杂 |
| Pinecone | 托管服务、简单易用 | 有成本 |
| Qdrant | Rust 实现、性能高 | 生态较小 |

### 结论

当前实现支持 Milvus 和 Pinecone，可根据需求切换：

```typescript
// 向量存储服务
@Injectable()
export class VectorStorageService {
  constructor(
    @Inject('MILVUS_CLIENT') private milvus?,
    @Inject('PINECONE_INDEX') private pinecone?,
  ) {}
}
```

## ADR-009: 内容生成策略

**状态:** 已接受
**日期:** 2026-05-09

### 背景

需要通过 AI 自动生成品牌相关的内容，包括 SEO 文章、FAQ、JSON-LD 等。

### 决策

```
┌─────────────────────────────────────┐
│          输入: 品牌信息               │
│   名称、描述、产品、价值观等          │
└─────────────────┬───────────────────┘
                  │
                  ▼
┌─────────────────────────────────────┐
│        知识库上下文检索               │
│   提取相关品牌知识作为上下文          │
└─────────────────┬───────────────────┘
                  │
                  ▼
┌─────────────────────────────────────┐
│        模板选择 + AI 增强             │
│   选择合适的内容模板                 │
│   结合上下文生成内容                 │
└─────────────────┬───────────────────┘
                  │
                  ▼

│          内容输出                    │
│   SEO 文章 / FAQ / JSON-LD / 产品描述│
```

| 内容类型 | 用途 | 格式 |
